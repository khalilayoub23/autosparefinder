# base_price writer inventory — closure pass (2026-11-01)

Authoritative registry: **`docs/BASE_PRICE_WRITERS.json`** (generated by `candidates/maint-safety-2026-11-01/evidence/gen_registry.py` from an
AST scan of the tree). `tests/test_base_price_writers.py` fails when the scan and the registry disagree, when a writer keeps its own
price formula, when an importer overwrites a non-empty `base_price`, or when a shell/SQL writer is unregistered.

`base_price` is INTERNAL (search tie-break, harvest targeting, admin export), never a customer price. Authority: `backend/price_policy.py`,
`docs/PRICE_POLICY.md`. Ownership:

| Part has… | base_price is | Owner |
|---|---|---|
| a customer-visible offer of its own class | policy net (cost × 1.45) of the cheapest such offer | `fix_base_prices` |
| no customer-visible offer | policy net of the catalog estimate (importer → max/1.18 → online) | `normalize_base_price` |
| only offers of another class / no input | unchanged | nobody |

Writers outside the two tasks and the cleanup healers may only **fill an empty value** with `price_policy.base_price_for_cost(cost)` (a known
ex-VAT cost) or `price_policy.base_price_for_estimate(...)` (only a consumer/VAT-inclusive list price is known). Never overwrite, never a local
`× 1.45`, never a spreadsheet / LLM / raw supplier figure.

## 1. Result

**60 Python writers + 1 shell writer discovered.** Final status: **3 VERIFIED_COMPLIANT, 12 FIXED_AND_VERIFIED
(incl. the shell script), 45 E2E_VERIFIED_FIXTURE, 1 E2E_VERIFIED_SAVED_SOURCE, 0 E2E_VERIFIED_LIVE_SOURCE, 0 BLOCKED_WITH_EVIDENCE.**
No writer is UNREVIEWED / UNKNOWN. All 60 are fixed in code (no literal formula, no unguarded overwrite — static tests).

The 46 writers that were `BLOCKED_WITH_EVIDENCE` after the closure pass were each run **as the real script, as a subprocess, against the isolated sandbox
database** (`tests/test_importers_e2e_scripts.py`, harness `tests/importer_e2e_harness.py`): source input → the script's own parsing → its own mapping →
`price_policy` → its own INSERT/UPDATE/UPSERT → the persisted `base_price` read back, for (a) a new part, (b) an existing part with an **empty** base (filled), (c) an
existing part with an **owned** base (kept), (d) a repeat run (idempotent). Inputs are SYNTHETIC fixtures built from each parser's contract (PDFs are real PDFs generated with
PyMuPDF; HTTP sources replace only the transport) — **none is a live-source run** (`E2E_VERIFIED_LIVE_SOURCE` = 0: the isolation has no outbound access and no live source was contacted).
`import_parts_db.py` ran on the REAL saved workbook in the repository (`E2E_VERIFIED_SAVED_SOURCE`). Israeli-vs-foreign VAT variation is `NOT_APPLICABLE` to these end-to-end runs: the policy's VAT choice is an offer/supplier property, and each importer here writes a single cost basis (the importer's ex-VAT or consumer figure), so the persisted value is asserted against `price_policy` directly; the foreign-supplier VAT rule is covered by the price-policy tests, not re-proven per importer.
**None remains blocked.** `importers/repair_manufacturer_import.py` (the last one) was closed by replacing pandas with `openpyxl` (already pinned in `requirements.txt` and present in the image) and fixing two further defects found by the run (host-absolute workbook paths, missing NOT NULL `manufacturer_id` on insert); it is a sentinel-only writer (inserts `base_price = 0.0`; a workbook price is never a base_price).

## 2. Admin Excel upload (`POST /api/v1/admin/parts/import`)
Traced: the UI (`frontend/src/pages/Admin.jsx`) listed `base_price` as an accepted optional column and showed "✅ הייבוא הושלם בהצלחה" with created/updated/skipped only;
the backend wrote the cell into `parts_catalog.base_price` (new and existing parts). No document, API contract or consumer defines the column as anything other than
the internal field, which the price policy now derives. **Behaviour now:** the column is **unsupported**: never written; the response carries
`unsupported_columns: ["base_price"]`, `prices_not_applied: N` and a Hebrew `warnings[]`; the UI help text no longer offers it, the sample table drops it, and an amber warning
is shown (`adminImportWarnings.js`, `adminImportWarnings.node-test.mjs` 3 passed). Tests: `test_admin_upload_does_not_type_a_price_into_base_price` (+ warning fields).
**Owner decision still open:** whether a sheet price should instead become an ex-VAT *cost* on a supplier offer (a different, approved workflow). `Admin.jsx` was edited but **not built** (no `node_modules` here).
